# Reuse cooperative numerical states and repair phase evaluation

The production arithmetic is in `strict/cooperative-satcom/positive_wick.py`
and `evaluate_positive_wick.m`. Both compute the unchanged conditional-Gaussian
model with a positive own-variance expansion. The original subtractive phase
functions remain available as controls. Source guards include the new provider.

[The actual evidence packet](../../strict/validation/cooperative-positive-wick-20261017/README.md)
contains complete original91-endpoint inputs, retained MP80 values and native
outputs, with executable saved-output checks in both languages.

`package_evidence.py` records existing183 cases, preserving every old false
flag and numerical failure, and packages the actual91-input/native evidence.
`unpack_evidence.py` requires a declared archive SHA and fresh destination,
rejects unsafe members and verifies every payload before writing it.
`audit_saved_components.py` checks all ordered8190 complex coordinates,
every criterion and original complete-gradient stop without solver calls.

`replay_saved_native.m` performs only the actual91 saved-state arithmetic.
`run_native_bank.m` is a distinct complete183-case optimization command: it
retains every original expanded input, all8 schemes and1000 moment draws per
completed point. It writes each result and keeps failures. Its first campaign
exposed an independent AP-QT native solver failure and was stopped for diagnosis;
existence of its progress file is not completion or success.
