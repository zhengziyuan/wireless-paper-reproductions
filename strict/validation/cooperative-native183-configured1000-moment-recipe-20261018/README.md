# Complete native183 configured1000 moment regeneration recipe

This recipe binds all183 original native input slots to67 exact channel-moment
input groups. It preserves complete1000-draw native second/fourth moments,
their independent reconstructed values, every MP80/MP100 expected-moment
reference, the original export headers and full r,G,d primitive byte hashes.
Every full original native JSON/MAT input is supplied by the separate complete
native183 phase/final/QT packet. No saved vector is replaced by its norm.

The complete raw operand banks total2735488000 bytes and remain in the
external numerical-data library. The small public recipe contains all
per-draw moment arrays and exact full-vector byte bindings. Materialize the
full operands with the unchanged declared MATLAB exporter before checking
physical received signals. The local fresh-regeneration QA receipt states
how many complete groups were actually regenerated and independently checked;
metadata/reference validation alone explicitly regenerates zero streams.

Each exact group uses the original configured1000 draws, fixed `phi=ones`,
declared Twister seed and complete original dimensions. The67 groups have
67000 distinct configured draws and represent183000 per-case configured
draws after exact input/seed/count/source grouping. This is a channel-moment
validation count configured in this reproduction. It is not a Monte Carlo
count recovered from the authors' optimized-performance numerical paragraph,
and the regenerated stream is not a recovered historical callback buffer.

With MATLAB R2025b and Python3.12, NumPy2.5.3, SciPy1.18.1 and mpmath1.4.1,
run the complete public route into a fresh numerical-data destination:

```text
python -B tools/cooperative-stable-replay/native183_moment_recipe_v1.py --recipe strict/validation/cooperative-native183-configured1000-moment-recipe-20261018 --native-packet strict/validation/cooperative-native183-complete-phase-final-QT-20261017 --matlab "C:/Program Files/MATLAB/R2025b/bin/matlab.exe" --output-dir E:/new-complete-native183-moment-replay
```

The runner restores/checks every full original input, regenerates all67 full
primitive streams, requires every raw byte hash to match, independently forms
every `h=d+G*r`, recomputes all per-draw second/fourth moments and both empirical
averages, checks the finite-Rician expected moments at MP80/MP100, and compares
all183 cases' saved MC metrics. Original optimization, phase-gradient and
performance-MC runs are not called. Full primitive operands and all new
independent reports are retained in the chosen output.

Fifteen invalid-evidence controls reject reduced populations/counts, changed
dimensions, seed changes, wrong case aliases, missing/changed full operand
bytes, substituted norms, missing per-draw rows, nonfinite values and changed
native sample-power bits. After a complete materialization, run:

```text

```

An optional `--native-restored` avoids restoring an already complete native
input packet, while checking every payload hash again. Local
`--reuse-exact-primitives-index` mode requires all67 complete binary banks and
explicitly reports zero newly regenerated native streams. It still freshly
reconstructs every received-signal moment and both precision lanes. The index
is a local path binding and is not included as a portable public input.

The separate manifest-verification tool checks all183 complete input bindings
and all67 saved per-draw array shapes/dtypes/finiteness. Its report explicitly
states zero full primitive banks read, zero native streams regenerated and
zero fresh independent moment calculations. It is suitable for a small CI
metadata gate; full fresh-vector scientific QA has its own separate receipt.

Neither gate establishes optimized-design performance MC, all original inner
states, author input recovery, dual-language curve identity, original-reference
agreement, global optimality or full-paper reproduction.
