# Case 13: saved-point MATLAB and Python evaluation

This record reports an actual same-input evaluation at eight saved AO points for one hotspot-satellite case (U=1, beta=20 dB), with two starts and four iterations per start. It does not establish that the MATLAB or Python optimizer reproduces the full paper, that either optimizer converges, or that any original figure agrees.

The MATLAB stage called the repository's original `strict_hotspot_statistical('evaluate', ...)` implementation. The Python stage executed the original `evaluate` function from `statistical.py`, extracted as an AST to avoid importing unrelated optimization dependencies. Both evaluated the same retained binary64 Q, Psi, W, and per-start final noise. A later check found that the eight saved QT_begin noise values match the corresponding final records bit for bit; see the [QT parameter evidence](../hotspot-case13-qt-parameter-evidence-v1/README.md). The historical-source limitations described there still apply. The saved Q was not independently reconstructed or proven to match the corresponding phase by this evaluation.

The accompanying `matlab-result.json` and `python-result.json` preserve the results of those actual executions. They cover eight points and 16 SINR values per point. MATLAB's saved-result differences were zero for all SINR values, rates, and powers. Between Python and MATLAB, the largest absolute SINR difference was approximately 3.176410245941952e-10, at a SINR of about 1517; the largest relative SINR difference was approximately 2.0938087674462268e-13. The largest absolute rate and power differences were approximately 3.019806626980426e-13 and 7.105427357601002e-14, respectively. These differences are observations, not a claim that an unreported tolerance was met.

Both stages exited naturally with code 0. The Python and MATLAB stages took approximately 1.391 and 51.641 seconds; the monitored task-root peak was 541,092 bytes. Monitoring was polling, not a hard filesystem quota, and does not prove that MATLAB, Java, or licensing components wrote nothing outside that root. MATLAB logged six warnings about stale CVX search directories. CVX was not used by the evaluation branch; no optimizer or solver was run. The warnings do not imply that those directories were recreated.

The source trajectory chunks and prior terminal records were not freshly authenticated, and individually locked reads do not establish a whole-event atomic snapshot. The two implementations use the same saved inputs; this comparison is not an independent experiment or validation of physical units. Earlier reconstruction of Q is a separate saved-input check and does not authenticate the historical data.

The original execution scripts used machine-specific paths and are not included as a portable rerun claim. The two result JSON files document the executed checks; a portable reproduction of this particular MATLAB/Python comparison remains to be prepared and verified. The original model implementations are under `strict/hotspot-satcom/`; the related compact saved-point evidence is under `tools/hotspot-case13-evidence-v1/` and `tools/hotspot-case13-hu-evidence-v1/`.
