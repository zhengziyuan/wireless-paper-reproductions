preserves the actual saved Python and MATLAB results, all accepted MRT/ZF

draw, failed history or source is removed to fit a publishing limit.

After the immutable sources/eight archive parts have been staged and the actual
fresh full200 publication gate has passed, the complete user command is:

```text
python -B verify_full200.py --verify-unpack-audit-render --new-output ../ma3-fresh-verification
```

The output must not exist and must be outside this bundle. At least 8 GiB free
space is checked at start; this is a start observation, not a whole-bank or
memory-fit guarantee. A single audit child runs with one BLAS/OpenMP thread.
Never use `-O` or `-OO`: original assertions are scientific acceptance gates.
Bytecode is disabled for the immutable support code and extracted evidence.

Python dependencies are listed in `requirements.txt`. The version pins reflect
the observed local numerical/display environment, not a promise that any
unverified runtime or BLAS build will reproduce identical solver states. No
Python runtime, MATLAB binary, solver binary or environment installer is shipped.

The command verifies the exact trusted index and every complete archive part,
extracts all 1044 original files into a NEW directory, then executes the existing
unchanged-math independent full200 saved-data audit. ALL200 physical, original
stop, input/source and coordinate gates must pass before the renderer runs.
Partial/survivor-only reports and exit-code-only success are rejected.

Two Figure 3 plots are written: one for the saved Python trajectories and one
for the saved MATLAB trajectories, with PNG/SVG and the complete plotted curve
JSON. Unequal converged trajectory lengths use explicitly declared terminal
hold; no fabricated updates or averaging of only successful cases is allowed.

This is a fresh independent audit of **saved dual-language results**, not a
fresh native MATLAB run, optimization rerun, new random ensemble or entire
paper reproduction. The MATLAB results are actual native saved results; this
command rechecks their own states using the independently implemented physical
and certificate formulas. Nonconvex Python/MATLAB solver trajectories need not
coincide. Global AO optimality, all unrecorded internal FPA matrices/KKT stages,
rigorous interval accuracy and recovery of the author's historical experiment
are not certified. The current reconstructed curves do not establish close
agreement with the original published figure.

Every failed or interrupted new output is retained. The command never deletes,
overwrites, relocates or relabels an earlier result. No plot is produced from a
failed full200 numerical gate.
